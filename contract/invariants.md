# Manager / worker invariants v1.0.0

状态：用户已批准实施。以下为 v1 实现基线；精确 wire 字段以 OpenAPI 为准。

## 无认证与开放注册

- manager 与 worker 接口无认证，不要求认证头、登录或注册密钥，不保留认证配置项。
- 任意 worker 可注册；不要求预配置身份、地址名单、人工准入或 IP 白名单。
- 请求结构、能力 schema、容量、重复标识与会话转换仍按协议校验。
- 执行 lease、epoch 与任务归属校验继续生效，仅承担一致性约束。

## 身份、能力与来源

- board_id、worker_id、instance_id 各有独立意义，不从 IP 或进程名称猜身份。v1 的 instance_id 表示进程启动会话。
- 能力声明区分支持的操作模式、组件实现、schema 版本、环境身份与当前 readiness。
- 直连、Push、Pull 共用本机接收、容量与执行引擎；来源适配器不能各自复制编译评估流程。
- worker 无 manager、注册失败或 manager 断连时，仍可接收直连任务并返回完整本地结果。

## 预分配与执行所有权

- assignment_id 表示尚未交付执行的容量预留；lease_id 表示执行租约，二者不可混用。
- Push 与 Pull 共用一个原子调度和 lease 授予入口，同一 attempt 只能有一个有效执行所有者。
- reservation 在确定尚无执行 lease 时可到期回收；派发状态不明时不得仅凭超时推断未接收。
- worker 观测心跳、capacity 广告与执行续租是不同协议。节点离线不等于执行已终止。
- execution lease 过期时不得直接跨板重跑；先核对旧进程、候选恢复及原 attempt 状态。
- 对事件、结果、取消和文件提交，均验证 job、attempt、worker、instance 与 lease/epoch 归属。

## 领取、幂等与容量

- claim_request_id 与请求摘要绑定；相同请求重试返回同份有效授予，不再领取新任务。
- worker 接收同 attempt 时查持久幂等索引；已接收或终结的任务不能再次启动。
- 同 client_request_id 同摘要复用原作业；异摘要冲突，具体响应由 OpenAPI 定义。
- 按资源池计数：直接任务占用 + 未转租约的预留 + 执行租约占用，不重复累加本机总负载。
- 本机资源许可是最终上限；网络重试、双通道及增加轮询协程不能增加实际执行槽位。
- 每个 worker 采用一个受控领取循环，领取数量由真实余量限制；停机禁止继续产生新领取。

## 持久化、回执与停止

- job、assignment、claim receipt、lease 和状态改变必须满足明确的原子提交边界。
- 本地终态、恢复证据与待发送报告在同一持久化边界落盘；发送失败不丢失终态。
- outbox 至少一次投递，manager 按事件身份/序号幂等处理；确认只更新对应事件。
- 未确认消息不得因保留期清理；已确认墓碑保留期必须覆盖重试窗口。
- claim 提交前、提交后交接前、交接后运行中三个停机边界都必须可恢复。
- Tokio future 被取消不等于认领回滚，也不等于外部进程已退出；必须保留认领与清理证据。

## 工件与评估事实

- compiler 产物绑定候选、编译参数、case 特化、目标硬件、工具链与环境摘要。
- 既有 SHA-256 / canonical JSON 摘要合同继续使用，不因参考 libacg 而改哈希算法。
- 输入使用不可变快照；输出使用 manifest 和实际大小/摘要确认，不暴露本机绝对路径为下载地址。
- 文件 IO 和哈希不持有长数据库写事务；文件提交必须受到执行租约约束。
- 必需证据尚未完成时，不报告完整成功；同时区分本地结果就绪与 manager 已确认。
- correctness、performance、编译分别记录状态；任务完成不自动表示数值通过。
- 不跨板继承测速参照，不把 func 的基础检查映射为数值正确性通过。

## 版本与兼容

- wire schema 的格式版本、任务定义版本和环境内容摘要分别记录。
- manager 只把任务分配给匹配定义版本和环境约束的 worker；不能仅匹配操作名称。
- 旧 evald 协议、func / timing 和新评估类型必须有显式兼容映射及样例。
- 按用户要求采用无认证接口；libacg 的媒体依赖与租约过期自动重试策略不默认迁入 rvbench。
