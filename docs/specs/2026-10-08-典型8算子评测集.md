# 典型 8 算子评测集 — 替代原 micro 集的设计与实施计划

- 状态：**待评审**（2026-10-08）；本次完成规划，接口接入、容差裁决与板上采集尚未实施。
- 替代：[2026-09-20 micro 集规划](2026-09-20-micro集.md)。本文件是后续实施入口，旧文件保留作历史记录。
- 依据：《8 个典型算子：接口说明与典型用例》（整理日期 2026-09-25，以下简称“来源文档”）。其接口与实现描述绑定 FlagGems `master`、HEAD `d17e23e48`，不是当前板上版本已支持的证明。
- 成员：`abs`、`aminmax`、`softmax`、`mv`、`mm`、`conv2d`、`topk`、`_flash_attention_forward`。最后一项展示名为 `flash_attention_forward`，实际调用符号保留下划线。
- 规模：**8 算子 × 10 用例 = 80 条计划记录**。先交付每算子一个来源典型用例（C01，共 8 条），再扩至 C02–C10；实际提交数由支持性探针与禁用门禁决定。
- 条目纳入仍遵循 [proposal → dev → beta → release 流程](2026-09-20-条目纳入流程.md)，集合入选不代表条目已经 `release`。

## 1. 目标与范围

以来源文档的 8 个算子替代旧 micro 成员，覆盖逐元素、双输出归约、归一化、矩阵向量乘、矩阵乘、卷积、值与索引选择、融合注意力八种接口形态。保留旧方案“小集合跑通输入构造、提交、参照、计时与落盘”的用途，调整选型依据与验收要求。

第一阶段准确复现来源典型用例的 shape、dtype、属性、值域及输出结构；第二阶段增加规模、对齐、布局和语义边界用例。所有测量绑定目标主机与软件版本，主目标平台仍为 RISC-V / SpacemiT K3。

目前已创建 specs 计划、spec.json 格式与首份 8 个 C01 的机器可读定义。构造器、参照实现、服务端适配和上板执行仍按 §8 分阶段交付；后续 C02–C10 逐项补齐，初版定义不等于可执行集已经验收。

## 2. 对原方案的替代决策

| 维度 | 原 micro 集 | 新计划 |
|---|---|---|
| 成员 | maximum / randn / log_softmax / median / addr / mv / apply_rotary_pos_emb / fused_adam | 按来源文档的 8 项替换，仅 `mv` 保留，但其典型用例重定 |
| 选型 | 每层简单、较难各一，覆盖随机与框架兜底判定 | 按八种算子接口与计算形态覆盖；不再要求每层各 2 个 |
| 分级 | 旧面板 L1–L4 | 来源分级 L1 四个、L2 一个、L3 两个、L4 一个；正式分级需按条目流程复核 |
| 主用例 | 既有面板主口径派生 | C01 逐项采用来源典型用例，C02–C10 明确标为本计划设计 |
| dtype | 全部 fp32 | `abs` 为 fp32，其余七项为 fp16；新增 fp16 数值合同依赖 |
| 正确性 | 可接受框架路径 `correct=None`；mv / fused_adam 为探索档 | 正式验收要求全部语义输出有判定；探索与未判定可留证据但不能算通过 |
| 禁用档 | 每算子 C07 固定登记不执行 | 风险按具体用例、版本与后端登记，不给八个算子套同一禁用条件 |
| 规模 | 80 作业（含登记档，计数含混） | 80 条记录；分别统计实际作业、跳过、待接入和失败 |

旧方案的四种判定路径、三种计时路径覆盖目标和预算不再作为新集合的验收条件。集合成员关系独立存放，不通过修改 `track` / `dev_flag` 表达，也不自动改变主指标分母。

### 3.1 接口归一化

- `abs`：v1 测非原地实数版本；`abs_`、复数输入及别名不增加成员，也不纳入本次 80 条。
- `aminmax`：输出必须保留两个张量。`dim=None`、负维与 `keepdim` 变体分别记录，不能只比 min。
- `softmax`：逻辑名与底层 `_softmax` 注册符号分开记录；适配器传入 `dim` 与 `half_to_float`。C01 输入/输出同为 fp16；升 fp32 的变体另列。
- `mv` / `mm`：每个输入独立定义 shape；验证收缩维一致。来源描述 fp32 累加，实际计算路径与累加类型由目标版本探针确认，不根据来源的 GPU 分支描述推定 K3 行为。
- `conv2d`：来源 `strides` → `stride`、`dilations` → `dilation`；C01 `pads=[1,1,1,1]` 为对称四边 padding，可映射为 `[1,1]`。不把任意非对称四边 pads 压缩成两维。C01 必须带 bias；接口的 `bias=None` 在扩展档单测。
- `_flash_attention_forward`：固定 `cumulative_sequence_length_q=None`、`cumulative_sequence_length_k=None`、`max_q=64`、`max_k=96`、`dropout_p=0.0`、`return_debug_mask=false`；`window_size_left/right=None`、`seqused_k=None`、`alibi_slopes=None`。变更 shape 后 max_q/max_k 随序列长度更新。采用来源的字面值 `scale=0.0884`，不悄悄替换为精确 `1/sqrt(128)`。

### 3.2 来源事实的使用边界

来源描述 Flash Attention 不支持 varlen，本计划只测定长前向，不测 dropout、反向、滑动窗口或 alibi。辅助输出的 shape/dtype 和无 dropout 时 seed/offset/p 的有效性需由固定版本证据明确，不能自行假设其为可逐元素比较的张量。

来源对 Conv2D note 的规模描述不一致，按 shape 计算 C01 输出为 131072 个元素；输入为 131072、权重为 36864、bias 为 64 个元素。来源中 Abs 的 “4M” note 也不用于规模计算：其输入为 1048576 个 fp32 元素（4 MiB）。

来源中的 Stream-K、Ascend DSA、远程 dot 等分支是上游实现说明，不是目标平台必须命中的验收路径；记录实际分支，若无法观测则明确写未知。

## 4. C02–C10：扩展用例设计

本节全部为**新设计的派生用例，尚未上板验证**。除表中覆盖项外，继承 C01 的 dtype、属性与值域；全部默认连续布局、固定 seed。表中 `同 C01` 指完整合同相同，不只是 shape 相同。

| 槽位 | 意图 | 规则 |
|---|---|---|
| C01 | 来源典型用例 | 严格采用 §3 |
| C02 | 小规模冒烟 | 保留输入/输出结构，缩小计算规模 |
| C03 | 退化边界 | 合法最小维度；属性随形状合法化 |
| C04 | 非 2 幂 / 非对齐 | 验证尾块与掩码 |
| C05 | 中小规模 | 缩小主用例的规模，不要求每项精确四分之一 |
| C06 | 规模上探 | 放大归约、收缩、空间或序列维 |
| C07 | 布局 / 实现约束 | 非连续、非最内维或通道补齐；先独立探针 |
| C08 | 参数语义 | 切换 dim / keepdim / groups / largest 等 |
| C09 | 数值 / 平局边界 | 确定性输入或特殊语义 |
| C10 | 复测 | 完整复制 C01 合同与输入 seed，重新提交独立作业 |

## 5. 输入定义与服务端接缝

### 5.1 当前已核实的接口缺口

2026-10-08 读取本地 `rvbench-kernel-server` 的 `board/bench_op.py`、`board/fallback_refs.py`、`clients/eval_pipeline.py`，发现：

| 现有行为 | 对新用例的影响 | 实施要求 |
|---|---|---|
| `_SPECIAL_SHAPE` 把 mv 固定为 `[512,512]`；`_vec` 自动生成向量 | C01 `[160,1024]` 与指定值域无法保真 | 显式 case 输入优先，不覆盖 shape，两侧使用同一份 A/v |
| TopK 特判固定 k=5 | C01 k=10、largest/sorted 变体无法保真 | 属性进入完整调用合同 |
| `_sp_conv` 自动构造 `(2C,C,3,3)` 权重且无 bias | C01 所需 Cout=64、bias 与值域无法保真 | 支持独立 x/w/bias 与 groups/stride/padding/dilation |
| 通用 arity 推断会生成同 shape 第二输入或默认参数 | 非方 mm、多输出归约与注意力无法依此保证合同 | 每算子显式构造与适配，检查实际输入及返回结构 |
| `norm_shape` 的字符串列表表示多个独立 case | 多输入 shape 列表会被误读为多次作业 | 输入列表与作业 case 列表分开编码；适配协议先定稿 |
| `_outputs_match` 将张量转 float，fp16 容差为 5e-2/5e-2 | 无法作为精确索引与新 fp16 合同的验收口径 | 数值与整数/结构检查分开；按 op/dtype 合同判定 |
| 框架兜底可使用其他 shape 并返回 `correct=None` | 有延迟不代表测到计划用例或判定通过 | 记录 actual inputs/attrs/path；任何合同漂移不算完成 |

这些是代码层核查，不是板上运行结论。Flash Attention 导出名、必选参数、五元组及后端支持仍须 M2 探针。条目流程曾记录 Conv2D lowering 与 Flash Attention 调参失败的历史，需复测新版本，不能推定已修复或仍失败。

### 5.2 机器可读定义（M3 交付）

定义格式现采用 [spec.json v1](2026-10-08-spec-json格式.md)，以 [suites/kernels/typical8/spec.json](../../suites/kernels/typical8/spec.json) 为单一集合定义，替代原建议的 `cases.yaml`。首份定义已落 8 个 C01，用例 C02–C10 在 M3 逐项补至 80 条；格式、Schema 与本地校验工具已创建，板上探针、构造/检查实现与数值合同仍未完成。每条至少表达：

额外的不公开测试保存在本地 `spec.hidden.json`，采用 [独立隐藏格式](2026-10-08-spec-hidden-json格式.md)，只能引用公开 spec 已定义的算子及检查合同。首版另有 8 条私有派生用例，独立统计，不计入上述 80 条公开扩展计划；实际参数不随公开文档分发。

| 字段 | 含义 |
|---|---|
| `suite_id / suite_version / case_id / op` | 集合版本、唯一用例 ID 与规范算子名，如 `typical8.abs.C01` |
| `entry_ref / call_symbol` | 现有条目引用与实际调用符号；不存在的条目经流程建立 |
| `inputs[]` | 有序 name、shape、dtype、layout/stride、value_range 或确定性生成规则 |
| `attrs / seed` | 完整属性、None 与 seed；不依赖未记录的运行时默认值 |
| `expected_outputs / check_ref` | 返回结构、shape、dtype、语义检查与数值合同引用 |
| `source / derivation` | 来源文档、原路径/case_id，或本计划派生槽位及理由 |
| `execution / reason / evidence` | 可执行、待接入或 skip 的调度标记及依据；不复用条目态/候选态 |
| `version_pin / timeout` | 固定软件版本、目标后端及按探针确定的资源限制 |

构造器在计时前生成输入；同 case 的 torch/FlagGems 两侧复用同一输入，必要时复制以隔离修改。布局适配、参考计算与输出检查放在计时区间外；调用级计时依照既有 `timing-contract.md`。框架回退只有在完整合同一致时才可作为执行路径，并明确记录路径。

每条结果保存 case_id、合同版本/hash、seed、实际输入 shape/dtype/stride、attrs、调用符号、版本与 host、执行路径、job_id、终态/失败原因、torch_ms/gems_ms、逐输出检查结果及误差。未执行条目的 job_id/延迟可为 null，并说明原因。

## 6. 正确性与容差

### 6.1 输出检查

| 算子 | 数值参照与额外语义检查 |
|---|---|
| `abs` | torch.abs；有限实数 C01 与扩展输入按精确值检查，shape/dtype 必须一致；±0.0 的符号要求在 M2 固定，不靠普通 allclose 掩盖 |
| `aminmax` | torch.aminmax；min、max 分别精确值检查；keepdim 和全归约 shape 独立检查；零符号规则同上 |
| `softmax` | 按 dim/half_to_float 的等价 torch 调用；比较输出并检查非负和沿 dim 归一化；归一化阈值随 dtype 写入合同 |
| `mv` / `mm` | torch.mv / torch.mm 与必要的高精度误差诊断；K 档变化采集误差；零输入变体必须满足零输出语义 |
| `conv2d` | torch.nn.functional.conv2d，完整复用权重/bias/属性；检查输出尺寸公式与 bias=None / groups 变体；误差考虑 Cin/groups × Kh × Kw 的收缩规模 |
| `topk` | torch.topk 的所选值；检查 int64 索引、范围、每行索引不重复、`gather(x,indices)==values`；sorted=true 时检查顺序；平局只要求合法选中，不要求与 torch 相同索引；sorted=false 按值多重集合比较 |
| `_flash_attention_forward` | 固定版本的等价定长注意力参照；以 fp32 构造 scaled QK、mask、softmax 与 V 乘积诊断 out，并计算 lse；参照按 `[B,S,H,D]` 显式变换布局；五元组全部按 §6.2 检查 |

TopK 的有限 fp16 输入有重复值，必须验证入选值多重集合与第 k 大/小阈值合法性；不能因平局直接比较 indices，也不能把大整数索引转 float 后用相对容差检查。

### 6.2 注意力的辅助输出

M2 确认五元组各位置的类型、shape、dtype、布局及有效性，形成 `expected_outputs`。`out` 和有效 `lse` 均必须完成数值判定；lse 的布局由适配器显式对应。无 dropout/debug mask 条件下，seed/offset/p 若被固定版本定义为占位或无效，按该合同检查类型/结构与有效性标记，并引用证据，不要求其逐元素与其他后端一致。

不能丢弃辅助输出后宣称整项通过。实际返回与版本合同不一致、缺少 lse 判定或无法解释辅助输出语义时，记未判定并阻塞正式验收。

### 6.3 容差裁决与报告

- 复用 `numeric-contract.csv` 与 `numeric-contract-resolutions.md` 的正本和裁决通道；来源文档没有给出 rtol/atol，本文不把旧 fp32 默认值套给七个 fp16 算子。
- M2 收集每个数值输出的 max_abs_err、相对误差诊断及归约/收缩长度，M3 形成 op × dtype × 适用范围的合同；阈值须有参照与累加方式依据，不能为通过候选而事后放宽。
- Abs、Aminmax、TopK 的有限实数选择值采用精确值检查；整数索引与结构单独严格检查。Softmax/Mv/Mm/Conv2D/Attention 的容差在 M3 裁决，未裁决前仅为探索记录。
- 正式通过要求实际合同无漂移、所有必需输出检查通过、数值合同已定稿且复测一致。`correct=False` 为检查失败；`correct=None` 为未判定并必须说明原因，不能计入通过数。
- 报告分别列计划 80 条、实际提交数、通过数、失败数、未判定数、待接入数与 skip 数；不得把待接入或 skip 算作完成测量。已有候选评估态词表保持其本义。

## 7. 支持性、计时与预算

先逐算子单进程运行 C02 小档，再运行 C01；发生编译失败、崩溃、超时或不支持 fp16 时保留证据，隔离失败算子继续探测其他成员。fp16 用例不自动降为 fp32；替代 dtype 仅可作为明确另立合同的诊断运行。

来源的 FlagGems `d17e23e48` 用作来源绑定，实际运行另记录 FlagGems/torch/triton/evald、后端、硬件与测量簇。升级后重做支持性探针，跨主机重定基，不直接并比速度。

沿用既有调用级计时合同，同 case 对应同输入、属性与 dtype；记录 warmup、rep、同步方式和重复计时稳定性。当前历史文档引用每作业固定启动约 20s，这只是排期假设：8 个典型用例启动项约 160s、80 条全提交约 1600s（26.7 分钟），均未包含编译、计算、复测和排队。

M2 实测启动与计算时间、峰值内存及大档超时后，给出逐算子预算和全量预计时长。C06 的 GEMM、卷积与注意力不按输入元素数线性估算耗时；不承诺沿用旧方案的 0.5–1.2 小时或双车道加速比。
