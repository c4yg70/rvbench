01部署拓扑

两侧单向耦合：工作站是代码正本与战役状态所在（EV_WORKSPACE 指向含 runs/、results/ 的工作区根），板是执行与落盘所在。 仓已独立于工作区，两者不再有目录相对关系。

实线＝跨机通道。板端作业可显式指定 executor=subprocess；warmfork 不可用时 服务端自动回退并计 evald_executor_fallback_total。

02作业生命周期

关键顺序：path_lock 先于计时锁、计时锁覆盖部署到恢复的整段、恢复完成才放锁—— 任一时刻同一部署路径只有一个作业处于 deploy→run→restore 区间内，因此不会出现"测到上一个作业残留代码"。

超时口径：默认 15 min，上限 30 min（timeout_default_min / timeout_max_min， 可被 perf.<lane>.timeout_min 与请求体覆盖）。

03车道与并发

三个评估器（feature flag perf/acc/func）各对应一条车道； 车道决定 核、并发、执行器、超时，evaluators.* 决定 开关与计时轮数， 顶层 perf 覆盖层只覆盖资源与调度（perf ＞ evaluators ＞ 旧扁平键）。

车道评估器worker核计时锁执行器用途
timingperf1（默认）/ 可多 8-15（A100）持分区锁warmfork 计时正口径；多 worker 时按核段均分、锁按 <index> 分区（ADR-0014）
correctnessacc3 4-6（X100）不持warmfork 并行正确性筛选；强制 warmup=0/rep=1、K3_LANE=correctness、OMP_NUM_THREADS=1
funcfunc2 4-5（X100）不持subprocess 功能验证；慢但隔离度最高（每作业全新解释器）

两把锁，职责不重叠

path_lock 管部署互斥（跨车道、跨实例，键是部署路径）； /tmp 计时锁管CPU 资源互斥（与手工 SSH 基准共用）。 前者避免候选错配，后者保证计时纯净。

执行器与回退

executor=warmfork 为默认；warmd 不可达/握手失败/自检异常时，服务端 自动改走 subprocess 重跑同一作业，并记 fallback 计数。

队列与背压

每车道一个待执行队列，queue_max=64 两车道共享，lane_queue_max 可逐车道收窄；满则 429，客户端内置 30/60/120/240s 退避并在预算内放弃。

04不变量与门禁

这些是"错了就看不出错"的那类约束——违反时结果仍然像成功，所以它们被写成不变量而不是注释。

部署-恢复自包含 ADR-0001

评估前备份原文件、断硬链写入候选，评估后按 manifest 恢复并回读 sha 校验。

门禁：manifest.json 每条应含 restored_sha256；缺该键 ＝该条目未恢复（板恢复后须先做此先验，见 README 回归门 §0）。

计时互斥（分区） ADR-0002 / 0014

单 worker 用 /tmp/k3_bench.lock；多 worker 按 <index> 分区。

门禁：多 worker 部署下，手工基准与回退路径须同时持有全部分区锁。

只预热不变量 ADR-0004

warmd 父进程只 import torch/triton；候选代码永远在 fork 出的子进程里从磁盘部署文件加载。

门禁：预加载项里不得出现 flag_gems/bench_*。

纯 stdlib、单文件直部署 ADR-0003

服务端零第三方依赖，靠 pssh --put 直接覆盖单文件部署（板上 FlagGems venv 无 pip）。

门禁：仓库里任何新增服务端依赖都须先过此决策。

路径白名单

只有 flag_gems/ops/**、flag_gems/runtime/backend/_spacemit/**、 scripts/{bench_op.py,bench_gemm.py} 可被部署；其余路径直接拒绝。

门禁：白名单改动＝契约改动，须与板端 scripts_root 同步。

字节冻结 部署单元

evald.py、warmd.py、evaldctl.sh、config.example.json、 dashboard.html、monitor/* 与板端逐字节一致（md5 见 CHANGELOG）。

门禁：改动须过板上 --selftest（234 PASS 基线）； 工作副本用 CRLF，故禁止对冻结物执行 git checkout/restore。

07审计发现 2026-09-20 静态审计

板不可达期间的代码审计结论（证据为行号，详见 CHANGELOG 遗留项）。标「板上门禁」者必须 在板恢复后先跑 --selftest 再上板，不在本地直接改。

#发现影响处置
R1 崩溃在 deploy→restore 之间时，_sweep_stale 只标 failed、不补 restore 安装树可能仍是候选代码 → 后续跑分静默失真（ADR-0001 要防的事） 已加先验板恢复先扫 manifest；根治改动走板上门禁
R2 restore_files 先删后拷：备份缺失时会删掉线上文件 槽位被清空，仅剩计数器可见 板上门禁改为写临时文件再 os.replace
R3 内嵌 selftest 完全不覆盖 HTTP 面（无 Handler 调用） 401/413/429/202/404、长轮询、SIGTERM 全无自动化验证 板上门禁补临时端口端到端用例
R4 Store.jobs 与长轮询 Event 无淘汰；_load_history 全量读 jsonl 长跑内存单调增长（history_mem 只管响应条数） 板上门禁淘汰策略 ＋ 启动剪枝
R5 ThreadingHTTPServer 无 socket 超时；flock 无超时 慢连接占用线程；卡死的手工持锁会长期堵住计时车道 板上门禁设超时并暴露等待指标告警
R6 evald 退出不回收 warmd（start_new_session，仅执行器出错时 kill） 每次重启残留一个握着预热内存的守护（撞 MemoryHigh/Max 限制） 板上门禁父侧回收 ＋ 存活指标
R7 面板与 /metrics 无 schema 版本闸；面板仍在查已退役的 evald_probe_success 指标改名会静默变成空图，看起来"像没数据"而不是报错 文档面板侧加版本断言；一处挂 ?prom= 灰度验证
